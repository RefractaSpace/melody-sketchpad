# MSK 형식 v1 (.msk) — 멜로디 스케치패드 전용 이진 파일

컴퓨터가 빠르게 읽고, 크기가 아주 작은 **우리만의 형식**이에요.
앱의 **저장** 버튼이 이 형식으로 저장하고, **내 프로젝트** 목록도 이 형식으로 브라우저에 보관해요.

| 곡 | 프로젝트 .json | 악보 .txt | **MSK (압축)** |
|---|---|---|---|
| Plum풍 1번 진행 (음 197개) | 8,139 B | 4,086 B | **544 B** (15배 작음) |
| 128마디 시험 곡 (음 1,152개) | 39,745 B | 8,078 B | **886 B** (45배 작음) |

## 1. 전체 모양
```
┌──── 머리 5바이트 ────┐┌──────── 몸통 (압축했으면 deflate-raw로 풂) ────────┐
 'M' 'S' 'K'  버전  플래그   청크 청크 청크 … CRC
  4D  53  4B   01   bit0 = 몸통 압축
                    bit1 = CRC 청크 필수 (지금 앱이 만든 파일은 항상 켜짐)
```
**청크** = `[종류 4글자 ASCII][길이: varint][내용 (길이만큼)]`
모르는 종류의 청크는 **건너뛰어요** → 나중에 청크를 늘려도 옛 앱이 깨지지 않아요.

## 2. 숫자 적는 법
| 이름 | 뜻 |
|---|---|
| `u8` | 1바이트 (0~255) |
| `varint` | 7비트씩 끊어서, 앞 비트가 1이면 다음 바이트가 이어짐. 0~127은 1바이트, 128~16383은 2바이트 |
| `str` | `varint 길이` + UTF-8 글자 |
| `tone` | `u8 밝기×100` `u8 어택×250` `u8 릴리즈×100` |
| `mix` | `u8 볼륨×200` `u8 팬×100+100` `u8 리버브×200` `u8 딜레이×200` `u8 저음+12` `u8 중음+12` `u8 고음+12` `u8 플래그(1=SC 2=뮤트 4=솔로)` |

## 3. 청크
### `INFO` 곡 정보
`str 이름` `varint BPM` `u8 으뜸음(0=C…11=B)` `u8 조(0 장조, 1 단조)` `u8 스냅` `u8 기본 길이` `u8 재생(0 PAT, 1 SONG)`
`u8 코드 소리` `u8 베이스 패턴` `u8 베이스 소리` `u8 드럼 키트` `varint 편집 중 패턴` `varint 편집 중 채널` `tone 코드 음색`

### `CHAN` 채널
`varint 개수`, 채널마다: `u8 종류(0 악기, 1 드럼)` `u8 악기 번호` `str 이름` `tone` `mix`

### `FXCH` 코드·베이스·마스터 믹서
`mix 코드` `mix 베이스` `u8 마스터 볼륨×200` `u8 사이드체인×200` `u8 리버브 길이(0~3)`

### `PATN` 패턴 (패턴마다 하나씩, 순서대로)
```
str 이름 · varint 마디 수
코드:  varint 개수, 코드마다  varint (앞 코드와 박 간격 − 1) · u8 (으뜸음×16 + 종류 번호, 255 = 멈춤)
음:    varint 채널 수, 채널마다  varint 채널 번호 · varint 음 개수
          음마다  varint 시작 차이(앞 음과) · u8 음높이(MIDI) · varint 길이(틱) · u8 세기×250
```
시간 단위는 **틱** (한 박 = 48틱, 16분음표 = 12틱). 시작을 "차이"로 적어서 숫자가 작아지고, 그래서 대부분 1바이트로 끝나요.
**음 하나 ≈ 4바이트**.

### `PLST` 플레이리스트
`varint 트랙 수` `varint 조각 수`, 조각마다(마디 순): `varint 패턴 번호` `u8 트랙` `varint 시작 마디 차이`

### `SMPL` 내 샘플 (있을 때만)
`u8 칸 종류(0 = 채널 번호, 1 = 이름)` `varint 채널 번호` 또는 `str 칸 이름` · `str 파일 이름` · `u8 기준음` · `varint 바이트 수` · 원본 소리 파일 바이트

### `PLEX` 조각 길이·시작 (있을 때만)
`varint 조각 수`, PLST와 같은 순서로 조각마다 `varint 길이(0 = 패턴 그대로)` `varint 건너뛸 마디`

### `PCOL` 패턴 색 (있을 때만)
`varint 패턴 수`, 패턴마다 `u8 색 번호(0 = 없음, 1~7)`

### `AUDC` 오디오 클립 (있을 때만)
`varint 개수`, 클립마다 `str 소리 번호표(au:…)` `str 이름` `u8 트랙` `varint 시작 틱` `varint 건너뛸 ms` `varint 길이 ms` `u8 크기(%)`, 끝에 `str 오디오 클립 믹서 설정(JSON)`. 소리는 `SMPL`에 같은 번호표로 들어가요.

### `BEND` 피치 벤드 (있을 때만)
`varint 개수`, 음마다 `varint 패턴` `varint 채널` `varint 시작 틱` `u8 음높이` `u8 반음+12` (같은 시작·음높이의 음에 붙여요)

### `ROUT` 출력·버스 (있을 때만)
`str JSON` — `{"o":{"#채널번호 또는 chords/bass/audio":"bus1|bus2"}, "b":{"bus1":{믹서 설정}}}`

### `SAUT` 곡 자동화 (있을 때만)
`str JSON` — `{"대상|값":[[곡 틱, 값×1000], …]}`, 대상은 `#채널번호`·`chords`·`bass`·`audio`·`bus1`·`bus2`·`master`, 값은 `vol cut pan rev dly fx1 fx2 fx3`

`FXSL`의 종류 번호: 0 채널 · 1 코드 · 2 베이스 · 3 마스터 · 4 오디오 클립 · 5 버스 1 · 6 버스 2

### `TEMP` 정밀 BPM
`varint BPM×100` (예: 126.5 → 12650). `INFO`에는 반올림한 정수 BPM도 들어 있어서, 이 청크를 모르는 옛 앱은 정수로 읽어요.

### `CRC ` 검사 값 (항상 맨 끝)
`u8×4` = 이 청크 앞의 몸통 전체(압축을 푼 뒤)의 **CRC32** (작은 쪽 바이트부터). ZIP·PNG와 같은 계산법이에요.
읽을 때 다시 계산해서 다르면 "파일 일부가 바뀌었어요"로 거절해요. 플래그 bit1이 켜져 있는데 이 청크가 없어도 거절해요.
바이트 하나가 바뀌는 경우는 **전부** 잡혀요 (테스트: 296번 중 296번).

### `IDS ` 번호표 (브라우저 안 저장용)
`varint 채널 수` `str 채널 ID…` `varint 패턴 수` `str 패턴 ID…` — 내 샘플이 채널 ID로 연결돼 있어서, 브라우저에 보관할 때만 넣어요.

## 6. 곡 코드 (글자로 주고받기)
`MSK1.` + (MSK 파일 바이트를 base64url로 바꾼 글자). 메시지로 보내고 앱의 **붙여넣기**에 넣으면 열려요. 내 샘플은 빠져요.

## 7. 형식 자동 인식 (스캔)
불러오기·붙여넣기·변환기는 **파일 이름이 아니라 앞부분 바이트**를 보고 형식을 정해요.
| 앞부분 | 형식 |
|---|---|
| `4D 53 4B` + 32보다 작은 버전 바이트 | MSK |
| `4D 54 68 64` ("MThd") | MIDI |
| `MSK1.` 로 시작하는 글자 | 곡 코드 |
| `{` 로 시작 | 프로젝트 .json |
| `# 멜로디 스케치패드 악보`, `[채널]`, `[패턴]`, `BPM:` … | 악보 .txt |
